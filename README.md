# B站弹幕点歌机器人（网易云音乐）

观众在直播间发 **`点歌 歌名`**，机器人自动在网易云搜索、排队、用本机播放器放出来。
不需要任何开发者凭证，用你自己的网易云账号扫码登录即可（VIP 账号能放会员歌曲）。

```
B站弹幕  ──►  blivedm  ──►  解析指令  ──►  网易云搜索  ──►  点歌队列  ──►  本地播放器
             (WebSocket)                     (本地 API 服务)                (mpv/pygame)
```

---

## 一、跑起来（全程两次双击）

> 前置：电脑上已装 **Node.js ≥ 18** 和 **Python ≥ 3.9**。
> 检查命令：`node -v`、`python --version`

### 第 1 次：装依赖

双击 **`install.cmd`**。它会依次：装 300 来个 npm 包（几分钟）→ 建虚拟环境 → 装 Python 依赖
→ 问你要不要下载 mpv（推荐要，见下文「播放器选择」）。

### 第 2 次：扫码 + 运行

双击 **`login_netease.cmd`**，用手机网易云 App 扫弹出的二维码。登录成功后 Cookie 自动写进
`config.json`，**有效期通常几个月**，失效了再扫一次就行。

然后双击 **`run.cmd`** —— 完事。

```bat
run.cmd
```

`run.cmd` 是**一键运行**，它一个窗口里帮你做完这些：

1. 自动启动网易云 API 服务（已经在跑就直接复用，不会重复启动）
2. 等它真正就绪再往下走（首次启动要注册匿名 token，会慢几秒）
3. 启动弹幕点歌机器人（没配直播间号的话会直接问你要，输一次自动存进 `config.json`）
4. **你按 Ctrl+C 或关窗口时，自动把 API 服务一起收掉**，不留后台进程

> 为什么推荐用它：原来的做法要开两个窗口（一个跑 API、一个跑机器人），
> 关的时候还容易漏掉 API 服务。`run.cmd` 只留一个窗口，收尾干净。

参数会原样传给机器人：

```bat
run.cmd --room 1234567     临时指定直播间号
run.cmd --stdin            键盘模拟点歌，不连直播间（测试用）
run.cmd --list-backends    看有哪些播放器可用
run.cmd --keep-api         退出时保留 API 服务
run.cmd --no-browser       不自动打开浏览器（面板照常启动）
run.cmd --no-web           完全不要网页面板
run.cmd --web-port 9000    换面板端口（默认 8765）
run.cmd --verbose          把收到的每一条弹幕都打印出来（排查用）
run.cmd --autoplay         开启空闲随机播放（覆盖配置）
run.cmd --no-autoplay      关闭空闲随机播放（覆盖配置）
```

### 浏览器控制台（会自己弹出来）

启动时除了控制台窗口，还会自动打开一个浏览器页面 `http://127.0.0.1:8765/`：

- **当前播放**：歌名、歌手、音质、点歌人，带进度条
- **收到的弹幕**：实时弹幕流 + 累计条数 + 命中的点歌条数（★ 标记）
- **队列**：接下来要放哪些歌、谁点的
- **运行状态**：直播间连上没、收到多少弹幕、网易云登录没、用的哪个播放器
- **最近日志**：和控制台一样的内容，直接滚动查看
- **控制按钮**：切歌 / 暂停 / 继续 / **■ 停止播放** / 音量滑块 / 清空队列 / **空闲随机播放开关**
- **点歌**：直接在面板上搜歌点歌，**不用发弹幕**（见下）

适合这两种情况：控制台窗口被直播软件挡住了，或者你干脆把它最小化了。
页面每秒自动刷新，**只监听 `127.0.0.1`，外网访问不到**。

### 在面板上点歌

面板中间有个点歌框，输入歌名回车（或点「搜索」）会列出 8 条候选，每条右侧有「点这首」。

- **搜完再挑**：点「搜索」→ 从结果里选。候选会标出时长和 `VIP` 标记，方便挑对版本
  （搜「晴天」出来的第一条常常是翻唱，从列表里挑原版更准）。
- **直接点第一首**：不想挑就点「直接点第一首」，按和弹幕点歌**完全一样**的规则挑
  （优先名字对得上的那条）。

面板点歌和弹幕点歌走同一套规则：**查重、队列上限、时长上限都生效**，
不会重复点同一首歌。唯一区别是**面板点歌不受冷却限制** ——
冷却本来是防观众刷屏的，主播自己操作没必要拦。

面板点进来的歌，点歌人会显示成「网页面板」，方便和观众点的区分开。

### 空闲时自动放歌（随机播放）

没人点歌的时候，与其干等着，不如自己放点背景音乐。面板的按钮区有个 **「空闲随机播放」**
开关，勾上就生效（也可以在 `config.json` 里设 `autoplay.enabled: true`，或启动时加 `--autoplay`）。

规则：

- **只在队列空且没有歌在播的时候**才补歌，一次补一首 —— 不会把队列塞满
- **观众点的歌永远优先**：补进来的随机歌排在队列最后，有人点歌就按顺序放观众点的
- **会自动避开最近放过的 40 首**，不会来回循环同一批（`avoid_repeat` 可调）
- 随机歌的来源（`autoplay.source`）：

  | 取值 | 来源 | 说明 |
  |---|---|---|
  | `auto`（默认） | 先私人FM，再用关键词 | 最省心 |
  | `fm` | 私人FM | 登录后是真个性化推荐；实测**未登录也有内容** |
  | `recommend` | 每日推荐 | 一次约 30 首，未登录也有 |
  | `keywords` | 你配的关键词随机搜 | 完全可控 |

- 随机播放进来的歌，控制台显示成 `空闲随机`（而不是"点播：某人"），
  面板的当前播放也会显示「空闲随机播放」，一眼能区分

> ⚠️ **点「■ 停止播放」会把手动把随机播放一起关掉。** 否则刚停完两秒，
> 随机播放又接上一首，"停止"就白按了。需要的时候在面板上重新勾上即可。

`keywords` 默认是 `["轻音乐", "纯音乐", "华语流行", "钢琴曲", "民谣"]`，
按你直播间的调性改就行。

关掉它：`run.cmd --no-web`；想留着面板但不自动开浏览器：`run.cmd --no-browser`。

> 💡 **不小心关掉了浏览器标签页？** 面板是**机器人进程**提供的，关标签页**不会**停掉任何东西。
> 重新打开 `http://127.0.0.1:8765/` 就行 —— 双击 **`open_panel.cmd`** 也能帮你打开。
> **建议把这个网址收藏到书签栏**，以后一键就回来了。
>
> 但如果连**控制台窗口**一起关了（或者点了 ×），那机器人就真停了，得重新双击 `run.cmd`。

### 搬到别的电脑上跑

整套东西是**可迁移**的：拷到另一台 Windows 上就能用。但有一条铁律：

> ⚠️ **虚拟环境（`.venv`）不能跨电脑拷贝。**

`.venv/pyvenv.cfg` 里记着创建它那台机器上 Python 的**绝对路径**。
拷到别的电脑后那个路径不存在，虚拟环境就废了 —— 直接用通常报一堆看不懂的错。

所以正确做法是**让目标机器在本机重建**：

```bat
make_portable.cmd
```

它会生成一份干净的副本（默认在项目旁边，叫 `qdgj-portable`），并且：

- **不带** `.venv`、各种缓存、`config.json`（里面有登录 Cookie）—— 避免把本机状态带过去
- **带上** `netease-api/node_modules` 和 `tools/`（mpv 便携版）—— 这两样是可移植的，
  带过去能省掉几分钟的 npm install，mpv 也直接可用
- 加 `--zip` 顺便压成压缩包（约 70MB）

到新电脑上只要三步：

1. 把 `qdgj-portable` 整个拷过去（**放哪都行**，路径有中文、空格都没事）
2. 装好 **Python 3.9+** 和 **Node.js 18+**，然后双击 **`install.cmd`**
   （它会在本机重建虚拟环境，并自动识别出拷过来的旧 env 并删除重建）
3. 双击 **`run.cmd`** 开跑

> 路径带中文和空格是支持的 —— 所有脚本都用 `%~dp0` 相对定位，
> 源码里没有任何写死的绝对路径（有自动化测试 `tests/portable_test.py` 守着这条）。

**忘了先跑 install.cmd 会怎样？** 启动脚本会先做一次环境自检
（`_check_env.cmd` → `bootstrap.py`），检测到虚拟环境是别的电脑上建的，
会直接告诉你"请重新运行 install.cmd"，而不是丢一堆报错。

### 想分开跑也行

需要单独开窗口跑 API（比如机器人要反复重启）时，用这两个：

- **`start_netease_api.cmd`** —— 只启动 API 服务，**这个窗口要一直开着**。
- **`start_bot.cmd`** —— 只启动机器人，需要 API 服务已经在跑。

## 二、配置直播间

**直接粘直播间网址就行，会自动变成房间号。** 三种填法任选：

**① 启动时按提示输**（推荐，最省事）：`run.cmd` 没配房间号时会问你：

```
还没配置直播间号。
可以填纯房间号，也可以直接粘直播间网址，例如：
  1934302095
  https://live.bilibili.com/1934302095
  https://live.bilibili.com/1934302095?broadcast_type=0
  手机 App 分享出来的 b23.tv 短链也认
------------------------------------------------------------
请输入直播间号或网址（直接回车退出）：
```

粘进去回车即可，会自动写进 `config.json`，下次不用再输。

**② 启动参数**：`run.cmd --room https://live.bilibili.com/1234567`

**③ 编辑 `config.json`**（填网址也行，启动时自动归一成数字）：

```json
{
  "bilibili": {
    "room_id": "https://live.bilibili.com/1234567"
  }
}
```

### 认得哪些写法

| 输入 | 结果 |
|---|---|
| `1934302095` | ✅ 纯房间号 |
| `https://live.bilibili.com/1934302095` | ✅ 标准网址 |
| `...?broadcast_type=0&is_room_feed=1` | ✅ 带参数的网址 |
| `live.bilibili.com/1934302095` | ✅ 没带 http 也行 |
| `https://live.bilibili.com/blanc/1934302095` | ✅ 活动页 |
| `https://live.bilibili.com/h5/1934302095` | ✅ 手机页 |
| `https://m.bilibili.com/live/1934302095` | ✅ 移动端 |
| `https://b23.tv/AbCdEf` | ✅ App 分享的短链（会联网展开） |
| `【哔哩哔哩】我的直播间 https://...` | ✅ 整段分享文案直接粘 |
| `直播间号：1934302095` | ✅ 带说明文字 |
| `１９３４３０２０９５` | ✅ 全角数字 |
| `https://space.bilibili.com/1234567` | ❌ 这是**用户空间**，会明确告诉你不是直播间 |
| 文本里有好几个数字 | ❌ 会告诉你分不清，而不是瞎猜一个 |

认不出来时会给出**具体原因**（而不是闷声失败或猜一个错的），并提示正确格式。

> 短链展开需要联网。如果网络不通，会提示你"把网址在浏览器里打开后复制完整地址"。

### 自检

双击 **`check_env.cmd`**，它会把依赖、API 服务、登录状态、播放器、直播间配置全查一遍。
全绿就可以下一步了。

### 启动

双击 **`start_bot.cmd`**。控制台会打印收到的每条点歌指令和播放状态。

## 三、弹幕指令

| 弹幕 | 作用 | 权限 |
|---|---|---|
| `点歌 晴天` | 点歌（`点歌晴天`、`点歌:晴天`、`点歌，晴天` 也都认） | 所有人 |
| `队列` / `歌单` | 查看当前队列 | 所有人 |
| `帮助` | 显示指令列表 | 所有人 |
| `停止` / `关闭音乐` | **立刻停止播放**，并清空待播队列 | 房管 |
| `切歌` / `下一首` | 跳过当前歌曲 | 房管 |
| `暂停` / `继续` | 暂停、继续播放 | 房管 |
| `音量 50` / `音量+` / `音量-` | 调整音量 | 房管 |
| `清空` | 只清空待播队列，当前这首继续放完 | 房管 |

> 「停止」和「清空」的区别：**停止**是马上闭嘴（当前这首也断掉），
> **清空**只是不再往下放、让当前这首放完。两种需求都常见，所以都留着了。

**权限说明**：默认只有**主播本人**和 `config.json` 里 `request.admin_uids` 列出的 uid 能用控制类指令。
想让所有人都能切歌，把 `request.allow_everyone_control` 改成 `true`。

## 四、可选：让机器人回发弹幕

默认机器人只在**控制台**打印反馈，不会往直播间发弹幕。想让它回一句「已点《晴天》」：

1. 浏览器登录 B站，按 `F12` → Application → Cookies → `https://live.bilibili.com`
2. 找到 `SESSDATA` 和 `bili_jct` 两个值，填进 `config.json`：

```json
{
  "bilibili": {
    "sessdata": "你复制的 SESSDATA",
    "bili_jct": "你复制的 bili_jct"
  }
}
```

> ⚠️ 这两个值等同于你的账号凭证，**不要截图发出去、不要传到网上**。
> 只填 `SESSDATA` 也能收弹幕，但回发弹幕必须两个都有（`bili_jct` 是发送接口的 csrf 校验）。

### 顺便说一个不配 Cookie 的实际影响：观众昵称会看不到

不登录 B站时，B站会推一条 `LOG_IN_NOTICE`：

> 为保护用户隐私，未登录无法查看他人昵称

也就是说**弹幕本身照样能收到、点歌照样能用**，但 `uname` 是空的，点歌记录里会显示成
`用户<uid>`（程序已自动兜底，不会出现空白）。想要显示真实昵称，就把 `sessdata` 填上。

## 五、播放器选择

启动时会自动探测，优先级从高到低：

| 后端 | 起播速度 | 暂停 | 实时调音量 | 说明 |
|---|---|---|---|---|
| **mpv** | 几乎瞬间 | ✅ | ✅ | **推荐**，直接流播 |
| ffplay | 快 | ✅ | ❌ | 需要装 ffmpeg |
| **pygame** | 慢几秒 | ✅ | ✅ | 已装好，先整首下载再播 |
| wmp | 慢 | ❌ | ❌ | Windows 自带，兜底用 |
| null | — | — | — | 不出声，仅测试用 |

### 强烈建议装 mpv

双击 **`get_mpv.cmd`**，它会把 mpv 便携版下到 `tools/mpv/`，**不需要管理员权限，不污染系统**。
装好后机器人会自动优先用它，不用改任何配置。

> 这些第三方 mpv 构建用了 BCJ2/LZMA 压缩，`py7zr` 和 Windows 自带的 `bsdtar` 都解不开，
> 所以脚本会自动下载 7-Zip 官方独立版 `7zr.exe`（600KB，放在 `tools/`）来解压。

验证：

```bat
start_bot.cmd --list-backends
```

### pygame 后端的预下载

如果你用 pygame，程序默认开启 `player.prefetch`：**上一首还在播的时候就把下一首下好**，
轮到的时候直接开播，基本没有等待。不想要就把 `config.json` 里的 `prefetch` 改成 `false`。

## 六、常用配置项（`config.json`）

```jsonc
{
  "bilibili": {
    "room_id": 0,              // 直播间号，必填
    "sessdata": "",            // 可选，B站 Cookie，用于收弹幕/回发弹幕
    "bili_jct": "",            // 可选，回发弹幕必需
    "reconnect_delay": 10      // 掉线后重连等待秒数
  },
  "netease": {
    "api_base": "http://127.0.0.1:3000",
    "cookie": "",              // 扫码登录后自动写入，不用手动改
    "level": "exhigh"          // 音质：standard/higher/exhigh/lossless/hires
  },
  "player": {
    "backend": "auto",         // auto/mpv/ffplay/pygame/wmp/null
    "volume": 70,              // 0-100
    "cache_dir": "cache",
    "prefetch": true           // 预下载下一首
  },
  "request": {
    "prefixes": ["点歌", "!点歌", "/点歌"],
    "max_queue": 20,           // 队列上限
    "user_cooldown_sec": 30,   // 同一个人点歌冷却
    "max_duration_sec": 600,   // 拒绝超过 10 分钟的歌
    "admin_uids": [],          // 额外授权的 uid
    "allow_everyone_control": false,
    "log_all_danmaku": false   // true = 每条弹幕都打印（等同 --verbose）
  },
  "web": {
    "enabled": true,           // 是否启用浏览器控制台
    "host": "127.0.0.1",       // 只监听本机，别改成 0.0.0.0
    "port": 8765,              // 端口被占用会自动往后找
    "open_browser": true       // 启动时自动打开浏览器
  },
  "autoplay": {
    "enabled": false,          // 没人点歌时自动放随机歌
    "source": "auto",          // auto/fm/recommend/keywords
    "keywords": ["轻音乐", "纯音乐", "华语流行", "钢琴曲", "民谣"],
    "avoid_repeat": 40,        // 避开最近放过的多少首
    "retry_delay_sec": 5       // 取不到歌时等多久再试
  }
}
```

**音质建议**：VIP 用 `exhigh`（320k，省带宽）或 `lossless`（无损）。
如果某首歌拿不到指定音质，程序会自动逐级降级重试，不会卡住。

## 七、文件说明

| 文件 | 作用 |
|---|---|
| **`run.cmd`** / `run.bat` / `run.py` | **一键运行**：自动拉起 API 服务 + 机器人，退出时一起收掉 |
| `install.cmd` | 一键装依赖（会自动识别并重建无效的虚拟环境） |
| `bootstrap.py` / `_check_env.cmd` | 启动前环境自检（换电脑后能不能跑，看它） |
| `make_portable.cmd` / `make_portable.py` | 打包成可迁移副本（不带 .venv，可加 `--zip`） |
| `login_netease.cmd` / `qr_login.py` | 扫码登录网易云，保存 Cookie |
| `start_netease_api.cmd` | 只启动本地网易云 API 服务（**必须常开**） |

.venv\Scripts\python.exe tests\webui_test.py

### 常见问题

**「捕捉不到弹幕」/ 控制台一片安静，不知道到底收到没有**

这是最常见的困惑，先分清三种情况：

1. **房间没开播** → 没有弹幕流，控制台当然是安静的。**这是正常的。**
   你可以在直播间页面确认一下是不是真的在直播。
2. **弹幕在正常收，但没人发点歌指令** → 程序默认**只对点歌指令有反应**，
   其他弹幕是静默跳过的（免得刷屏）。所以"没输出"不等于"没收到"。
3. **真的收不到** → 往下看。

**怎么确认到底收到没有**，三种办法任选：

- **看网页面板的「收到的弹幕」卡片** —— 最直观。连上后如果有弹幕，会一条条滚出来，
  命中点歌的还会标 ★。顶部还有个「弹幕」徽章显示累计条数和"几秒前"。
- **加 `--verbose`** 启动：`run.cmd --verbose`，收到的每一条弹幕都会打印到控制台。
- **跑诊断**：
  ```bat
  .venv\Scripts\python.exe tests\diagnose_danmaku.py
  ```
  它会自动找几个**正在开播**的房间，分别用"原版鉴权"和"补 buvid 鉴权"连上去，
  统计心跳/弹幕/礼物的条数，直接告诉你弹幕能不能收到。

程序还有个**弹幕监视**：连上 60 秒一条弹幕都没收到，会自动在控制台提醒你，
并提示"房间没开播时是正常的"。

> 实测结论：弹幕捕捉本身是好的。在人气 84 万的房间上，原版鉴权 20 秒内就收到
> 10 条弹幕、首条 1.7 秒到达。所以如果收不到，先确认房间**正在开播**。

**报 `blivedm.client.InitError: init_room() failed`，或者一直刷「X 秒后重连」**
→ 这是 B站风控，**跟你的房间号没关系**。blivedm 原版用 `xlive/web-room/v1` 下的
  `getInfoByRoom` / `getDanmuInfo` 做房间初始化，而这两个接口现在会被风控直接拒掉
  （返回 `code=-352`，连房间 1 这种官方房间也一样），于是 `init_room()` 永远失败。
→ 本项目已改用不受影响的**老接口** `room/v1`（`room_init` + `Danmu/getConf`）绕开它。
  如果你还看到这个错，说明代码是修复前的版本，用下面两条命令确认一下：
  ```bat
  .venv\Scripts\python.exe tests\diagnose_bilibili.py
  .venv\Scripts\python.exe tests\live_connect_test.py --room 你的房间号
  ```
  第一条会逐项告诉你哪层断了（并说明 `-352` 属于预期、不影响使用），
  第二条真连一次弹幕服务器，输出「整条弹幕链路通畅」就没问题。

**双击 `run.cmd` 一闪而过 / 提示找不到 `run.bat`**
→ 文件名是 `run.cmd`，另外也提供了等价的 `run.bat`，两个都能用。
→ `run.cmd` 结尾有 `pause`，出错时窗口不会自动关，往上翻就能看到原因。

**搜不到歌 / 报「无法连接网易云 API 服务」**
→ 用 `run.cmd` 的话它自己管这个，重启一次就行。
→ 用 `start_bot.cmd` 的话，检查 `start_netease_api.cmd` 的窗口是不是关了，重启它。

**VIP 歌唱到一半就停 / 提示「只能试听片段」**
→ 网易云 Cookie 失效了，重新跑 `login_netease.cmd`。

**没有声音**
→ 跑 `start_bot.cmd --list-backends` 看选中的后端。
→ 用了 `null` 说明一个播放器都没探测到，运行 `get_mpv.cmd`。

**切歌/暂停没反应**
→ 只有主播和 `admin_uids` 里的人有权限，确认发指令的账号对不对。
→ `wmp` 后端不支持暂停，换 mpv 或 pygame。

**关掉窗口后音乐还在放**
→ 这是**已经修好的问题**。原因：用户点控制台窗口的 × 或用任务管理器结束时，
  Windows 直接 `TerminateProcess`，Python 的 `try/finally` 根本来不及跑，
  被 spawn 出来的 mpv 就成了孤儿进程继续放。
→ 现在所有播放器子进程都会被放进一个 **Windows 作业对象**（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），
  父进程一死，Windows 会自动把子进程一起收掉。这个兜底能覆盖强杀、崩溃等所有情况。
→ 想验证：`.venv\Scripts\python.exe tests\orphan_test.py`（会做 A/B 对照实验）。
→ 万一还有残留（比如跑的是修复前的版本），手动清一下：
  ```bat
  taskkill /F /IM mpv.exe
  ```

**弹幕收不到**
→ 确认 `room_id` 填对了（是直播间号，不是短号也没关系，程序会自动解析）。
→ 部分直播间需要登录才能收弹幕，填上 `sessdata` 试试。

## 九、技术说明

### 为什么用本地 API 服务

[网易云官方 ncm-cli](https://github.com/neteasecloudmusicapi/ncm-cli) 需要走开发者入驻申请 AppID/Key。
本方案改用社区维护的
[`@neteasecloudmusicapienhanced/api`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced)
（原 `Binaryify/NeteaseCloudMusicApi` 的续作，[原仓库已因版权原因删库停更](https://www.donews.com/news/detail/4/3967225.html)，
npm 包仍在维护），跑在本机 `127.0.0.1:3000`，**不需要任何开发者凭证**。

> 这个服务只监听本机回环地址，不对外网开放。

### 线程模型

```
主线程          asyncio 事件循环，跑 blivedm 收弹幕，只解析+入队，绝不阻塞
解析线程        处理点歌：搜索、校验时长、去重入队
播放线程        取歌、解析播放地址、调播放器阻塞播放
预下载线程池     把队列里下一首的音频提前下好
```

收弹幕的协程里做得越少越好——blivedm 的消息处理和接收在同一个协程，
阻塞它会直接卡住弹幕流，所以耗时的活全部丢给工作线程。

### 几个实现细节

- **`blivedm` 的 brotli 依赖**：PyPI 上 blivedm 0.1.1 把 `brotli==1.0.9` 写死了，那个版本在
  Python 3.13 上要源码编译且编不过。`install.cmd` 的做法是先装小写 `brotli`（有现成 wheel，
  模块名相同），再用 `--no-deps` 装 blivedm。
- **切歌的返回值**：pygame 后端切歌时会先调 `mixer.music.stop()`，这会让 `get_busy()` 立刻变
  `False`，看起来像"正常播完"。所以播放循环结束后必须再确认一次 `stop_event`。
- **音频地址**：网易云有时返回 `http://`，部分播放器会拒绝，统一转成 `https://`。
- **`netease-api/serve.js`**：原版 `app.js` 启动时会 `exec` 调 npm 检查版本，在受限环境下会
  直接崩。这里换成 `checkVersion: false` 的启动器。
